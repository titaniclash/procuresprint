Components

Every part a module screen is allowed to use, with its variants and states. Each maps 1 : 1 to an MUI component themed by theme/mui-theme.js. Everything here is interactive: tab, click and use the keyboard.

Buttons

One primary action per view. Secondary is outlined; tonal for frequent in-page actions; text for low-emphasis. Destructive actions confirm in a dialog.

MUI: Button variant contained / outlined / text, IconButton.

Order in a footer: text (cancel) → secondary → primary, right-aligned. Labels are verbs + object ("Submit for approval", not "OK").

Inputs

Label always above the field, never inside it. Optional fields are marked, required ones are not (most are required). Errors say what to do.

MUI: TextField (outlined), Select, Autocomplete, DatePicker.

Action tiles

The system's signature. A tile shows a count of work and filters the list below when pressed. Tone comes from the top rule; the selected tile turns tint. Use 3–5 per page, ordered by urgency.

MUI: CardActionArea with aria-pressed.

Data table

The one table. Toolbar → saved views → applied filters → bulk bar (on selection) → rows → pager. ID column is frozen; money is right-aligned in tabular figures. Density switches between 48 and 36 px rows. Under 600 px rows become cards.

MUI: DataGrid (Pro for pinning) or Table + custom toolbar.

Overlays

Menu for row and page actions. Dialog only to confirm or to ask one short thing. Drawer to preview or edit a record without leaving the list. Tooltips name icon buttons; they never hold information found nowhere else.

Feedback

Inline alerts explain a state of the page. Toasts confirm an action and offer Undo; they never carry errors that need a decision. Skeletons replace content while loading; spinners only inside buttons.
